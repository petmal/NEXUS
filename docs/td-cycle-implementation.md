# Bounded T/D cycle: implementation record

## Phase 1 — evidence diagnostics

Add typed witness payloads and a family-owned witness producer to revision inference.
Attach them only to extended operator diagnostics. Retain source turns, archive
identity and rejection provenance. Add summary counts and binding metadata without
breaking bounded stderr capture. Test prior-evidence-only behavior and non-leakage.

## Phase 2 — explicit interventions

Add validated revision options for single-shot finish and public-readings checking.
Disclose them in public evidence/manifest and preserve default behavior. Integrate
the opt-in checker with session/client/HTTP boundaries and public exchange logging.
Test gates, strict inputs, state/trace immutability, repeat calls, replay, and the
distinction between consistency with evidence and actual correctness.

## Phase 3 — qualified evaluation bundle

Create a typed role-specific matrix, exact structural descriptors, source-bound
preflight, baseline panels and generated tasks. Select qualified nonduplicated
high-horizon candidates; retain separately labeled contrasts. Generate 24 baseline,
10 single-shot and 6 consistency executions, with model assignments stated. Preserve
all artifacts as operator-only unless explicitly player-safe. Do not run models.

## Phase 4 — bounded prototypes and findings

Execute small selective-revision/control and two-module composition analyses using
the existing primitive law and exact finite-machine utilities. Report actual gates,
controls, shortcut results, limits and runtime; reject claims that do not survive.
Keep uncalibrated prototypes outside the production family registry.

## Phase 5 — review and handoff

Run focused and repository regression checks, qualify the resulting matrix, review
the diff independently, and fix supported findings. Package ordered Git patches,
preflight evidence and run instructions. Stop where fresh live outcomes determine
the next choice. Explain any environment checks not executed.

## Decisions from implementation

- Keep concrete witnesses in a separately versioned private report, preserving terminal performance schemas. The first support point includes canonical state identity; it does not assert support persistence for other families.
- Use boolean reading consistency for the assisted condition. Exclude finish feedback explicitly; no hidden-truth or enumerating service oracle is introduced.
- Preserve the original hard admission criteria. C4/L5 candidates are lower-memory contrasts, and the corrected 6467 certificate is two readings.
- Pin the whole harness template in source, canonicalize every service input and reject incomplete preflight artifacts. This bounds the custom-template surface to the reviewed experiment.
- Reject W4 on physical reachability and downstream-only NW2 on decision identifiability. Do not register either as a production family. A richer intervention/control design would require a later scoped decision.
- Keep provider/harness telemetry in an explicit operator ledger. The standalone service cannot supply provider stop reasons or parser outcomes.
- Apply all patches before validating: global legacy source bindings are refreshed in the final commit after actual proof/conformance gates.
- Stop before live model evaluation. Docker/Podman and MindTrial were unavailable; image/harness validation remains an operator preflight step.
