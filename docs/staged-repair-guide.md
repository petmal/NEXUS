# Staged repair pilot

`staged-repair-v1` is an opt-in ontology on axes v2. It preserves all earlier
families. The player clears nine hidden loads across three portable seal components,
using the same artificial mechanisms to interpret experiments and apply repairs.
The exact physical state determines victory; neither a theory essay nor a unique
description of the law is required.

## What changed and what was proved

- A partial repair is insufficient: all three seals must be present and correct.
  Independent enumeration finds 216 distinct complete repair signatures for the
  216 T3 worlds. A treatment that works in one cannot silently cover another.
- D3 gives independently accessible experiments. D4 couples each reader's useful
  setting to the preceding mechanism. Both use the same physical repair law and
  same world at a matched seed. These are explicit family-specific v2 profiles,
  not v1's exact probe-count guarantees.
- T2 discloses the three exponents, leaving shifts to infer. T3 hides exponents
  and shifts. T0/D0 supplies exact mechanisms and repairs as an execution control.
  T1 and other D values are rejected rather than assigned unproved semantics.
- A public adaptive policy needs at most six readings. The exact minimum fixed
  identifying panel is nine readings in D3 and fifteen in D4. Setup and treatment
  costs are included separately in live preflight; both fixed panels fit R1.
- Per-world evidence can be substantially cheaper. With oracle choice of readings,
  D4 needs only three or four actual results to establish a guaranteed repair;
  D3 ranges from three to six. The matrix records this exact smaller quantity.
- Failed finishes remain legal. The uniform-prior success bound counts both
  readings and finishes: with k feedback actions, at most 3^(k-1) distinct mission
  signatures can be covered (capped at the prior size). For T3, five feedback
  actions cover at most 81/216. This relaxation grants free setup and arbitrary
  repairs, so it also covers guess-and-retry strategies. It is not an exact
  environment-action optimum or a failure probability for curated seeds/models.

The proofs cover 20 profiles: linked one/two/three-mechanism PoCs, the live
independent three-mechanism profile, and all eight T2 exponent disclosures under
both context modes. They compare the production tables to a separate scalar
oracle. Fixed-panel lower bounds are checked again using equivalence partitions.

**Depth admission remains false.** These results establish information requirements
and an experiment-selection advantage, not an unavoidable deep cognitive process.
In particular, a downstream reader can reveal the preceding route. This makes
some D4 episodes require fewer supporting readings than their D3 counterparts.
T2 can sometimes identify a preceding shift without directly measuring that stage.
Those are valid scientific inferences and remain legal.

## Validated ten-execution matrix

Every row uses P1/R1, a fresh service/context, no external Python, extended private
diagnostics and a 120-tool-call allowance. Rows 02–09 have 40 environment actions;
row 10 has 46. The independent versus dependent pairs keep the exact physics,
target and budget fixed. Operator seeds and proof metadata must not enter prompts.

“Minimum certificate” means the smallest set of actual reading outcomes that
supports a guaranteed repair, granting oracle experiment choice and free setup,
excluding finish feedback. It is not a guaranteed player policy. “Reference” is
the achieved public-policy action count. Relative challenges are hypotheses for
the pilot, not calibrated model scores.

## Complete player-level example: row 04, seed 59

The seed number is operator-only. The player starts in stores with three seals,
tagged 0,1,2. Each starts with cumulative doses [0,0,0]. There are optional fresh
survey stocks for each tag. The array contains reader, trimmer and anneal.
All arithmetic is modulo 3; every experiment remains legal throughout.

Before acting, the manifest and evidence disclose:

1. Stage i has F_i(u)=(u+k_i)^e_i, where shift k_i is 0,1,2 and exponent e_i is 1 or 2.
   Every combination is possible. The six local functions at tags 0,1,2 are:

   | Shift | Exponent | Responses |
   |---:|---:|---|
   |0|1|[0,1,2]|
   |0|2|[0,1,1]|
   |1|1|[1,2,0]|
   |1|2|[1,1,0]|
   |2|1|[2,0,1]|
   |2|2|[1,0,1]|

2. Route r_i=(k_i+e_i-1) mod3. Reader settings are [stage,carrier]. The active
   carrier is 0 at stage 0 and the preceding stage's route thereafter. An active
   reader returns F_i(u); any other carrier returns 0. A zero does not by itself
   identify active versus inactive carrier.
3. The reading is from a freshly reconstituted baseline COPY. It does not measure
   the mission seal's current remaining load or change its treatment.
4. Trimmer settings are three incremental doses. Configure stores settings;
   operate adds them to that seal's cumulative doses d modulo 3. Current loads are
   F_0(u)-d0, F_1(u)-d1-r_0*d0, and F_2(u)-d2-r_1*d1.
5. Finish requires all three actual seals carried in array with every current
   load zero. It returns only success/rejection. Anneal clears one specimen's
   doses for one action; it preserves the world and spent budget.

The following walkthrough uses only that public information and returned results:

1. Take all three seals and move to array (four actions).
2. Configure reader [0,0]. Probe tag 0: result 0, leaving shift 0 with either exponent.
   Probe tag 2: result 1, establishing exponent 2. Therefore route 0=1.
3. Configure reader [1,1]. Probe tag 0: result 1, leaving three local functions.
   Probe tag 1: result 1, establishing shift 1/exponent 2. Therefore route 1=2.
4. Configure reader [2,2]. Probe tag 0: result 1. Probe tag 1: result 0, establishing
   shift 2/exponent 2. None of these six readings changed a mission seal's doses.
5. Derive the following initial loads and complete cumulative treatments:

   | Seal tag | Inferred baseline loads | Desired cumulative doses |
   |---:|---|---|
   |0|[0,1,1]|[0,1,2]|
   |1|[1,1,0]|[1,0,0]|
   |2|[1,0,1]|[1,2,0]|

   For tag 0, the middle dose 1 also subtracts r_1 * 1 = 2 from the last load 1.
   The final dose must therefore be 2: 1-2-2=-3=0 modulo 3. Treating each load
   independently would produce the wrong final state.
6. For each seal, configure its three-dose row and operate trimmer on that seal.
   Doses were initially zero, so these settings are the desired cumulative doses.
   A subsequent correction would instead apply desired-current modulo 3.
7. Finish successfully; return the actual victory_code. Total: 20 charged actions.

This is a transparent reference solution. It uses six readings even though an
oracle can select a four-reading certificate for this world. The qualifier records
that distinction and accepts any other correctly supported treatment sequence.

## Build and run

Use both files in `examples/mindtrial/`: `nexus-staged-config.yaml` and
`nexus-staged-tasks.yaml`. Provider settings are retained from the previous pilot;
Astra medium is enabled, other runs disabled, and keys blank. Set credentials
locally. The prompts follow the current manifest across both mission families.

From the repository root at the delivered feature-branch commit:

```sh
podman build --build-arg VCS_REF=$(git rev-parse HEAD) -t nexus:staged-repair-v1 .
podman run --rm --entrypoint python nexus:staged-repair-v1 scripts/preflight_staged_repair.py --output /tmp/staged-preflight.json
```

Replace `podman` with `docker` if appropriate. Do not run the model matrix if
preflight fails. The image keeps the standard OCI revision label and canonical LF
handling. All generation and terminal telemetry remains operator-only during play.
